# الفصل السادس

## المبادئ غير القابلة للتفاوض (Non-Negotiable Rules)

يحظر في المشروع:

- وضع منطق الأعمال داخل Views.
- وضع منطق الأعمال داخل Serializers.
- وضع منطق الأعمال داخل React Components.
- الوصول المباشر بين Domain وآخر.
- إنشاء API بدون Contract.
- إضافة جداول بدون مراجعة Domain.
- كسر حدود الـ Multi-Tenant.
- تعديل قاعدة البيانات مباشرة خارج آلية الـ Migrations.
- إدخال منطق خاص بعميل (Tenant) داخل النواة المشتركة للنظام.

# الفصل السابع

## المبادئ التقنية (Technical Principles)

### Backend

- Django هو الإطار الرسمي.
- Django REST Framework هو طبقة الـ API.
- PostgreSQL قاعدة البيانات الرسمية.
- الاعتماد على Services وUse Cases في منطق الأعمال.
- استخدام Background Jobs للأعمال طويلة التنفيذ.

### Frontend

- Next.js هو الإطار الرسمي.
- React App Router هو الأساس.
- TypeScript إلزامي.
- كل واجهة تعتمد على API Contracts.
- يمنع الوصول المباشر إلى قاعدة البيانات من الواجهة.

# الفصل الثامن

## مبادئ البيانات (Data Principles)

- يوجد مالك واحد فقط لكل كيان (Single Source of Truth).
- لا يسمح بتكرار البيانات دون مبرر موثق.
- كل البيانات قابلة للتتبع (Auditability).
- كل تغيير جوهري يجب أن يسجل.
- لا يجوز حذف البيانات الحساسة حذفًا دائمًا إلا وفق سياسة واضحة.

# الفصل الحادي عشر

## مبادئ الذكاء الاصطناعي (AI Governance)

أي وكيل AI يعمل على المشروع يجب أن:

1. يقرأ الدستور أولًا.
2. يحدد الـ Domain المتأثر.
3. يراجع القرارات المعمارية ذات الصلة (ADR).
4. يحلل أثر التغيير.
5. يقترح خطة التنفيذ.
6. ينفذ ضمن حدود المهمة.
7. يحدث الوثائق إذا تغير السلوك أو التصميم.

ولا يجوز له تجاوز هذه الخطوات.

---

## ما أود إضافته قبل الانتقال إلى المرحلة التالية

أرى أن **Enterprise Constitution** يجب أن يظل ثابتًا ونادر التغيير. لذلك أقترح أن نضيف فوقه مباشرة وثيقة ثانية ستكون الأكثر استخدامًا أثناء التطوير، وهي:

> **Engineering Playbook v1.0**

وهذه لن تكون وثيقة نظرية، بل دليل عملي يجيب عن أسئلة مثل:

- كيف نضيف Domain جديد؟
- كيف ننشئ Model أو Service أو API أو شاشة جديدة؟
- كيف نراجع Pull Request؟
- متى نستخدم Event؟ ومتى نستخدم Background Job؟
- متى نعدل كودًا قائمًا، ومتى ننشئ مكونًا جديدًا؟
- ما هي قائمة التحقق (Checklist) التي يجب أن يمر بها أي تغيير قبل دمجه؟

أعتقد أن هذا سيكون المستند الذي ستستخدمه أنت ووكلاء الذكاء الاصطناعي يوميًا، بينما يبقى **Enterprise Constitution** هو المرجع الحاكم الذي تُبنى عليه جميع القرارات.
