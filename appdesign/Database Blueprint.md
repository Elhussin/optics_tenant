**الحالة: معتمد للمشروع**

## 1. بنية وتوزيع قاعدة البيانات (Multi-Schema Tenant Architecture)

يعتمد النظام على محرك قاعدة البيانات **PostgreSQL** ويطبق عزل البيانات للمستأجرين عبر نمط **Multi-Schema** باستخدام حزمة `django-tenants`. يتم توزيع البيانات على نوعين من المخططات (Schemas):

### أ. المخطط العام (Public Schema)
يحتوي على البيانات المشتركة بين جميع العملاء ولا يتم تكراره.
*   **جداول إدارة المستأجرين:** `Client` (المستأجرين)، `Domain` (النطاقات وعناوين الويب).
*   **جداول الاشتراكات والخطط:** خطط الأسعار (SaaS Plans)، مدفوعات الاشتراكات التأسيسية.

### ب. مخطط المستأجر (Tenant Schemas)
يتم إنشاء مخطط مستقل لكل عميل (مثال: `tenant_client1`, `tenant_client2`). يحتوي المخطط على جداول الأعمال التشغيلية الخاصة بهذا العميل فقط:
*   مخازن، منتجات، مبيعات، فواتير، محاسبة، سجلات المرضى، الموظفين، والوصفات الطبية.

## 2. مواصفات الفهارس المحسنة (Database Indexing Blueprint)

لضمان جودة الأداء عند وصول الجداول لملايين السجلات، نلتزم بالفهارس القياسية التالية:

### أ. الفهارس الفريدة والتأمين (Unique Constraints)
*   **الفاتورة (Invoice):**
    *   `invoice_number`: فريد لضمان تسلسل مرجعي سليم للفاتورة.
    *   `invoice_uuid` (لأغراض ZATCA): فريد على مستوى قاعدة البيانات لمنع تكرار معرّفات الفواتير المشفرة.
*   **المنتج (Product Variant):**
    *   `sku`: فريد على مستوى المستأجر لرمز الصنف لضمان جرد دقيق.

### ب. الفهارس المركبة للاستعلامات الشائعة (Composite Indexes)
*   **Order Indexing:**
    *   `[status, -created_at]`: لتسريع شاشات المبيعات الحالية ومراجعة الطلبات المعلقة.
    *   `[customer_id, -created_at]`: لتسريع شاشة الملف الشخصي للعميل وعرض طلباته السابقة.
    *   `[branch_id, -created_at]`: لتسريع لوحة التحكم الخاصة بالفرع وتصفية البيانات بحسب الفرع النشط.
*   **Invoice Indexing:**
    *   `[status, -created_at]`: لتسريع التقارير الضريبية وفواتير ZATCA المعلقة.
    *   `[customer_id, -created_at]`: لتسريع الفواتير المستحقة على العميل.
*   **StockMovement Indexing:**
    *   `[stock_id, -created_at]`: لتسريع تقارير كرت الصنف (Item Ledger) وتتبع حركات صنف معين.
    *   `[movement_type, -created_at]`: لتسريع تقارير المشتريات والمبيعات السنوية.

## 3. آلية الحذف اللطيف (Soft Delete Strategy)

*   لحماية البيانات الحساسة من الفقدان العشوائي، ترث جميع النماذج التشغيلية من `BaseModel` الذي يقدم حقل `is_deleted` (نوع Boolean بقيمة افتراضية `False`).
*   **الفهرسة:** يتم تصفية البيانات تلقائياً في الـ Django Managers عبر إدراج تصفية `is_deleted=False`.
*   مستقبلياً، عند الحاجة لفلترة سريعة للبيانات المحذوفة، يتم إضافة فهرس جزئي (Partial Index) بالشكل التالي:
    ```sql
    CREATE INDEX idx_active_orders ON sales_order (branch_id) WHERE is_deleted = FALSE;
    ```
