# ⚙️ معمارية الواجهة الخلفية وتعدد المستأجرين (Multi-Tenancy Architecture)

تعتمد الواجهة الخلفية لنظام `osmBack` على معمارية معقدة وموثوقة تضمن عزل بيانات كل عميل (Tenant) تماماً على مستوى قاعدة البيانات.

---

## 🏛️ عزل المستأجرين (Schema Isolation via django-tenants)

يستخدم النظام مكتبة `django-tenants` لتنفيذ معمارية Schema-per-tenant في قاعدة بيانات PostgreSQL:

1. **المخطط العام (Public Schema):**
   - يحتوي على جدول المستأجرين `Client` وجدول النطاقات `Domain`.
   - يحتوي على النطاقات العامة والاشتراكات والمستخدمين المشتركين.
2. **مخطط المستأجر (Tenant Schema):**
   - ينشأ مخطط برمجياً منفصل فور تسجيل مستأجر جديد (مثلاً `tenant_store1`).
   - يضم جداول المبيعات، المخزون، القيود المحاسبية، العملاء، والوصفات الطبية الخاصة بهذا المتجر فقط.

---

## ⚡ تحسين اتصالات قاعدة البيانات (Connection Pooling)

تم إضافة الإعداد التالي في ملف `osmBack/optics_tenant/settings/base.py`:
```python
DATABASES['default']['CONN_MAX_AGE'] = 600
```
هذا المتغير يضمن إعادة استخدام الاتصال بقاعدة البيانات لمدة 10 دقائق دون الحاجة لفتح وإغلاق اتصال PostgreSQL مع كل طلب HTTP، مما يضاعف سرعة استجابة الـ API ويحميه من الانهيار عند الضغط.
